| 项 | 值 |

| 对应标准 | **GB/T 32918.1-2016** 总则（= **GM/T 0003.1-2012**）<br>**GB/T 32918.2-2016** 数字签名（= **GM/T 0003.2-2012**）<br>**GB/T 32918.4-2016** 公钥加密（= **GM/T 0003.4-2012**）<br>**GB/T 32918.5-2017** 密钥生成（参数定义见 GM/T 0003.5-2012） |

## 4.1 曲线参数与标准参数定义（GM/T 0003.5 / GB/T 32918.5）的对应

| a | `FFFFFFFE FFFFFFFF FFFFFFFF FFFFFFFF FFFFFFFF 00000000 FFFFFFFF FFFFFFFC` | `SM2_sv.h:50`、`SM2_ENC.h` | ✅ |
| b | `28E9FA9E 9D9F5E34 4D5A9E4B CF6509A7 F39789F5 15AB8F92 DDBCBD41 4D940E93` | `SM2_sv.h:54`、`SM2_ENC.h` | ✅ |

> ⚠️ 这里是本实验踩过**最贵的一个坑**：`tools/drv_sm2_sv.c` 里我最初手抄 `b` 时
> 漏了第 5 个字节 `0x9D`（写成 `28E9FA9E 9F5E344D…`）。参数只错 1 字节，
> 曲线就换了一条 → **ZA 全错 → 签名全错**，但程序不报错、不崩溃，
> 表现为「签名互验就是过不去」，极难定位。
> 定位办法：用 Python 按标准公式独立算一遍 ZA，与程序输出对拍
> （GmSSL 密钥的 ZA 应为 `E9882429 1A501B3D 702DC356 3CCA2D80 6AD18E06 F54BA0E8 97DBEDA8 C15DE60C`）。
> 修正后两项签名互验立刻变 PASS。
> 详见 `docs/05-交叉验证与结论.md` §5.2。

## 4.3 签名与验签（GB/T 32918.2-2016 §5.5 / §6.1 / §6.2）

**ZA 的计算**（标准 §5.5）：

```
ZA = SM3(ENTLA || ID || a || b || xG || yG || xA || yA)
ENTLA = 0x0080（ID 为 16 字节时）
```

- 上游 `SM2_Sign` 的入参里 ZA 是**外部传入**的（`SM2_sv.c:263` 的注释写明
  `ZA=Hash(ENTLA||IDA||a||b||Gx||Gy||xA||yA)`），源码不自己算；
- 因此本实验在驱动 `tools/drv_sm2_sv.c` 里**按标准自己实现 ZA**
  （`compute_ZA()`，默认 ID `1234567812345678`，ENTLA=0x0080），
  这样才能验证「实现与标准一致」，而不是「实现与实现一致」。

**签名流程**（标准 §6.1）：

| 标准步骤 | 代码位置 | 代码写法 |
| --- | --- | --- |
| A1：`M = ZA \|\| M` | `SM2_sv.c:305-308` | `memcpy(M, ZA, 32); memcpy(M+32, message, len);` |
| A2：`e = SM3(M)` | `SM2_sv.c:310-312` | `SM3_256(M, M_len, hash);` |
| A3：随机 `k ∈ [1, n-1]` | 入参 `rand` | 驱动传入 |
| A4：`[k]G = (x1, y1)` | `SM2_sv.c:317-318` | `ecurve_mult(k, G, KG);` |
| A5：`r = (e + x1) mod n`，若 `r=0` 或 `r+k=n` 重选 | `SM2_sv.c:320-328` | `add(e, KGx, r); divide(r, n, rem);` |
| A6：`s = (1+d)⁻¹ · (k − r·d) mod n`，若 `s=0` 重选 | `SM2_sv.c:330-342` | `incr(dA,1,z1); xgcd(z1,n,…); multiply(r,dA,z2); subtract(k,z2,z2); multiply(z1,z2,s); divide(s,n,rem);` |

**验签流程**（标准 §6.2）在 `SM2_sv.c:372` `SM2_Verify`：
`r`、`s` 范围检查（`Test_Range`）→ `t = (r+s) mod n`，`t=0` 报错 →
计算 `(x1,y1) = [s]G + [t]P` → `R = (e + x1) mod n` → `R == r` 则通过。

**实测互验**（验证脚本第 6~10 项，全部 PASS）：

```
PASS  SM2 signature: drv_sm2_sv -> gmssl sm2verify
PASS  SM2 signature: gmssl sm2sign -> drv_sm2_sv verify
PASS  SM2 ZA: ours vs GmSSL (implied by mutual verify)
PASS  SM2 signature: tampered message must NOT verify
PASS  SM2 signature: tampered r must NOT verify in GmSSL
```

> DER 互操作要点：GmSSL 的 `sm2verify` 只吃 **DER 编码**的签名，
> 所以本实验写了 `tools/sm2_der.c` 做 `SEQUENCE{ INTEGER r, INTEGER s }` 的编解码。
> INTEGER 的编码规则必须与 GmSSL 一致：**去掉前导 0**；若最高位为 1 则前面补
> **一个** `0x00`；且**长度声明必须与实际写入字节数一致**——本实验第一次就是
> 这里写错（声明 33 字节、实际写 32 字节），GmSSL 报
> `asn1_length_le: 33 <= 32 failed` 并直接拒签。修正后互验通过。

## 4.4 公钥加密与解密（GB/T 32918.4-2016 §5.4 / §6.1 / §6.2）

**加密流程**（代码 `SM2_ENC.c:218` `SM2_Encrypt`，标准 §6.1）：

| 标准步骤 | 代码位置 | 代码写法 |
| --- | --- | --- |
| B1：`k ∈ [1, n-1]` | 入参 `randK` | 驱动传入 |
| B2：`C1 = [k]G = (x1, y1)` | `SM2_ENC.c:234-239` | `ecurve_mult(rand, G, C1);` 后 `big_to_bytes` 写入 `C`/`C+32` |
| B3：`[h]P` 不是无穷远点 | `SM2_ENC.c:241-244` | `ecurve_mult(para_h, pubKey, S);` |
| B4：`(x2, y2) = [k]P` | `SM2_ENC.c:246-248` | `ecurve_mult(rand, pubKey, kP);` |
| B5：`t = KDF(x2‖y2, klen)` | `SM2_ENC.c:250-255` | `SM3_KDF(x2y2, 64, klen, C + 96);` |
| B6：`C2 = M ⊕ t` | `SM2_ENC.c:257-259` | 逐字节异或 |
| B7：`C3 = SM3(x2 ‖ M ‖ y2)` | `SM2_ENC.c:261-266` | `SM3_process(x2y2,32); SM3_process(M,klen); SM3_process(x2y2+32,32);` |

**KDF**：`third_party/SM2349/src/KDF.h:44` `SM3_KDF`，
对应 GB/T 32918.4-2016 附录 A 的 KDF：用 SM3 做 CTR 模式计数器，
`ct = 1; for each block: Ha_i = H(Z || ct); ct++`，`K = Ha_1 ‖ Ha_2 ‖ …` 截取 klen。

**密文布局**：上游用 **`C1 ‖ C3 ‖ C2`**（C1 为 x‖y 各 32 字节、无 `04` 前缀；
见 `SM2_ENC.c:238-239` 写 `C` 与 `C+32`，`C3` 在 `C+64`，`C2` 从 `C+96` 开始），
与 GmSSL 的 DER 密文结构 `SEQUENCE{INTEGER x, INTEGER y, OCTET STRING C3, OCTET STRING C2}` 对应。

> ⚠️ 坑（第二个）：驱动最初打印的 `x=`、`y=` 是**接收方公钥**，
> 而 DER 里要放的是 **C1 的坐标**。两者混用会导致 GmSSL 用错误的 C1 去算
> `[d]C1`，进而 KDF 出来的密钥流全错，表现为
> `sm2_do_decrypt(): decryption failure`（而 DER 解析是成功的）。
> 改成驱动分别输出 `pubx/puby` 与 `c1x/c1y/c3/c2` 之后立刻通过。

**解密流程**（标准 §6.2）在 `SM2_ENC.c:288` `SM2_Decrypt`：
`C1` 是否在曲线上（`Test_Point`）→ `(x2,y2) = [d]C1` → `t = KDF(x2‖y2, klen)` →
`M' = C2 ⊕ t` → 重算 `C3' = SM3(x2‖M'‖y2)` 与 `C3` 比较，不等则报错。

**实测互验**（验证脚本第 11~13 项，全部 PASS）：

```
PASS  SM2 encryption: drv_sm2_enc -> gmssl sm2decrypt
PASS  SM2 encryption: gmssl sm2encrypt -> drv_sm2_enc decrypt
PASS  SM2 encryption: tampered C3 must NOT decrypt
```

> 注意：C3 的计算**不含 ZA**（GB/T 32918.4 的加密流程与 GB/T 32918.2 的签名流程不同），
> 这一点从 `SM2_ENC.c:261-266` 的三段 `SM3_process` 可以直接看出来。

## 4.5 与密标委标准列表的对应

密标委《标准列表》页面（<http://www.gmbz.org.cn/main/bzlb.html>）中与 SM2 相关的条目
（实测抓取，见 `artifacts/gmbz-norm-list.json`）：

| 行标号 | 标准名称 | 状态 |
| --- | --- | --- |
| GM/T 0003.1-2012 | SM2 椭圆曲线公钥密码算法 第1部分：总则 | 现行 |
| GM/T 0003.2-2012 | SM2 椭圆曲线公钥密码算法 第2部分：数字签名算法 | 现行 |
| GM/T 0003.3-2012 | SM2 椭圆曲线公钥密码算法 第3部分：密钥交换协议 | 现行 |
| GM/T 0003.4-2012 | SM2 椭圆曲线公钥密码算法 第4部分：公钥加密算法 | 现行 |
| GM/T 0003.5-2012 | SM2 椭圆曲线公钥密码算法 第5部分：参数定义 | 现行 |

本实验用到的是第 1、2、4、5 部分（密钥交换第 3 部分本次未做）。
`GM/T 0003.x` 与 `GB/T 32918.x` 是同一套算法的行业标准与国家标准版本，
代码中的参数定义、签名流程、加密流程与两版标准一致。

## 4.6 结论

- 曲线参数、ZA 计算、签名 A1~A6、验签、加密 B1~B7、KDF、密文布局，
  与 GB/T 32918 系列标准逐条对应；
- 附录 A.2 密钥向量、GmSSL 双向互验、篡改负例全部通过；
- 上游自检程序 `./SM2key`、`./SM2sv`、`./SM2enc` 退出码均为 0。
