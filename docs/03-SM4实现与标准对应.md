# 03 · SM4 实现与标准对应

| 项 | 值 |
| --- | --- |
| 对应标准 | **GB/T 32907-2016**《信息安全技术 SM4 分组密码算法》<br>**GM/T 0002-2012**《SM4 分组密码算法》（密标委标准列表第 0002 号） |
| 被测源码 | `third_party/SM2349/src/SM4.c`、`SM4.h` |
| 分组 / 密钥 | 128 bit / 128 bit，32 轮 |
| 本实验验证方式 | 国标附录 A.1 向量 + `gmssl sm4_ecb` + `openssl enc -sm4-ecb` 双向互验 |

## 3.1 标准 ↔ 代码对应关系

| 标准条款 | 标准要求 | 代码位置 | 代码写法 |
| --- | --- | --- | --- |
| GB/T 32907-2016 §5 | 128 bit 分组、128 bit 密钥 | `SM4.c:78` `SM4_Encrypt` | `unsigned char MK[]`、`PlainText[]`、`CipherText[]` 各 16 字节 |
| GB/T 32907-2016 §6.1 | 密钥扩展：异或系统参数 FK | `SM4.c:40-46` `SM4_KeySchedule` | `K[i] = SM4_FK[i] ^ MK[i]`（大端组装） |
| GB/T 32907-2016 §6.2 | 密钥扩展：轮函数 τ 与固定参数 CK | `SM4.c:48-58` | `tmp = K[i+1]^K[i+2]^K[i+3]^SM4_CK[i]`；`τ` 为 S 盒代换（`:53`） |
| GB/T 32907-2016 §6.2 | 轮密钥 `rk[i] = K[i+4]` | `SM4.c:58` | `rk[i] = K[i + 4];` |
| GB/T 32907-2016 §5.1 | S 盒（4 字节代换） | `SM4.c:53/93/142` | `SM4_Sbox[(tmp>>24)&0xFF]<<24 \| … \| SM4_Sbox[tmp&0xFF]` |
| GB/T 32907-2016 §6.2 | 非线性变换 `τ`、线性变换 `L`、异或 `⊕` | `SM4.c:88-93` | `tmp = X[i+1]^X[i+2]^X[i+3]^rk[i]`，经 S 盒后 `L` |
| GB/T 32907-2016 §6.2 | 轮变换：32 轮 | `SM4.c:88` | `for (i = 0; i < 32; i++)` |
| GB/T 32907-2016 §6.3 | 反序输出（逆向变换 R） | `SM4.c:104` 附近 | 32 轮后逆序输出 `X[35]…X[4]` |
| GB/T 32907-2016 §7.2 | 解密：逆序使用轮密钥 | `SM4.c:137-142` `SM4_Decrypt` | `tmp = X[i+1]^X[i+2]^X[i+3]^rk[31-i]` |
| GB/T 32907-2016 附录 A.1 | 示例：明文/密钥 `0123456789abcdeffedcba9876543210` → 密文 `681edf34d206965e86b3e94f536e4246` | `SM4.c:189` 附近（上游自检） | 上游自检内置该向量 |

## 3.2 实测：国标附录 A.1 向量

```bash
$ printf '0123456789abcdeffedcba9876543210' | xxd -r -p > /tmp/pt4.bin
$ ~/exp2/our/bin/drv_sm4 -key 0123456789abcdeffedcba9876543210 -in /tmp/pt4.bin
681EDF34D206965E86B3E94F536E4246
```

与 GB/T 32907-2016 附录 A.1 的示例密文一致。

> 坑（第一次就踩了）：一开始用 `echo "0123456789abcdeffedcba9876543210" > pt.bin` 喂的是
> **32 个 ASCII 字符**而不是 16 字节二进制，算出来当然对不上标准值。
> SM4 是分组密码，必须喂二进制：`printf '…' | xxd -r -p`。

## 3.3 实测：与 GmSSL / OpenSSL 互验

检测中心实现只提供**单分组 ECB 语义**（`SM4_Encrypt` 一次处理 16 字节），
所以对照命令也必须用 ECB 单块：

```bash
$ gmssl sm4_ecb -encrypt -key 0123456789abcdeffedcba9876543210 -in /tmp/pt4.bin -out /tmp/ct4_gm.bin
$ openssl enc -sm4-ecb -nopad -K 0123456789abcdeffedcba9876543210 -in /tmp/pt4.bin -out /tmp/ct4_os.bin
$ xxd -p /tmp/ct4_gm.bin
681EDF34D206965E86B3E94F536E4246
$ xxd -p /tmp/ct4_os.bin
681EDF34D206965E86B3E94F536E4246
```

三者（检测中心 / GmSSL / OpenSSL）密文完全相同。

反向再验一次——本实现加密的密文交给 GmSSL 解、GmSSL 的密文交给本实现解：

```bash
$ gmssl sm4_ecb -decrypt -key … -in ct4_our.bin -out pt4_back.bin     # 还原明文
$ ~/exp2/our/bin/drv_sm4 -key … -in ct4_gm.bin -dec                     # 还原明文
```

验证脚本对应 4 项：`SM4 vs gmssl sm4_ecb`、`SM4 vs openssl enc -sm4-ecb -nopad`、
`SM4 cross decrypt: gmssl ciphertext -> drv_sm4`、
`SM4 cross decrypt: drv_sm4 ciphertext -> gmssl`，**全部 PASS**。

## 3.4 结论

- 密钥扩展（FK/CK/τ）、轮函数、L 变换、32 轮结构、逆序输出、解密逆序轮密钥，
  与 GB/T 32907-2016 §6 完全对应；
- 附录 A.1 标准向量、GmSSL、OpenSSL 三方一致，双向解密闭环；
- 上游自检程序 `./SM4` 退出码 0。
