## 5.2 遇到的问题与解决过程

按时间顺序，全部是实际卡住过的点。

### ① 虚机被拖死，vmrun 一直等待

- **现象**：用 `vmrun copyFileFromHostToGuest` 逐个文件往虚机里灌源码，虚机无响应，
  `vmrun` 挂住不返回，SSH 也连不上。
- **处置**：先想硬复位，写成 `vmrun reset hard <vmx>`，报错
  `Error: Cannot open VM: C:\Users\lenovo\Documents\hard, unknown file suffix`
  —— 正确语法是 `vmrun reset <vmx> hard`（子命令在前，参数在后）。
  复位后虚机启动正常，`~/exp2/SM2349` 完好，只丢了同步失败的 `our/`。
- **根治**：改用 **SSH 免密 + scp 打包**，一次连接传一个 tar 包，
  不再逐文件走 vmrun。密钥 `~/.ssh/exp2_vm_ed25519`，见 `scripts/guest.ps1`。
- **反思**：往虚机里灌文件时，先想清楚「失败会不会把目标系统弄成不可用」。
  vmrun 的逐文件拷贝一旦中途断链，guest 侧会留下半截文件且进程挂死。

### ② 上游源码自带 `main()`，链接冲突

- **现象**：想把上游 `SM3.c` 和自己的驱动链接成一个可执行文件，出现
  `multiple definition of 'main'`。
- **解决**：用 `-Dmain=scctc_unused_main` 把上游入口改名后**重新编译**成 `.o`，
  再和驱动一起链接（见 `scripts/build_guest.sh`）。
- **反思**：这是「直接复用别人的 .o」和「复用源码」的分界线——
  想复用源码里的算法，就只能接受它的编译单元，重新编。

### ③ MIRACL Core 8.x 没有全局 `mip`

- **现象**：按老版本 MIRACL 的写法加 `extern miracl *mip;`，
  链接报 `undefined reference to 'mip'`；改用 `miracl *mip = mirsys(10000, 16);`
  之后，`drv_sm2_sv` 一调用就段错误。
- **解决**：查上游 `SM2_Init()` 的写法，照抄——在**函数内部**建局部实例，
  并设置 `mip->IOBASE = 16`（大端）。全局实例名在 8.x 里是 `mr_mip`，
  但用它反而不安全（生命周期跨文件）。段错误的根因是**用了没初始化过的 `mip`**。
- **反思**：段错误先怀疑「指针指向的全局状态没初始化」，而不是「代码逻辑错了」。

### ④ SM4 测试向量喂成了 ASCII 字符串

- **现象**：第一次跑 SM4，明文用 `echo "0123456789abcdeffedcba9876543210"` 生成，
  得到 32 字节 ASCII，和标准值对不上。
- **解决**：SM4 是分组密码，必须喂 16 字节**二进制**：
  `printf '0123456789abcdeffedcba9876543210' | xxd -r -p > pt.bin`。
- **反思**：标准向量通常是十六进制文本，测试时必须区分「字符串」和「字节序列」。

### ⑤ GmSSL 命令在脚本里挂死

- **现象**：`gmssl sm3 -in file` 在非交互 shell 里不返回。
- **解决**：所有 GmSSL 调用加 `< /dev/null`（必要时再套 `timeout`）。
- **反思**：命令行工具有交互式分支时，脚本化必须显式切断 stdin。

### ⑥ GmSSL 的加密私钥，OpenSSL 解不开

- **现象**：`gmssl sm2keygen` 生成的私钥 PEM 用 `openssl pkcs8` 读会失败。
- **原因**：GmSSL 3.2.0 的私钥 PEM 是 **PBES2 + PBKDF2-HMAC-SM3**
  （OID `1.2.156.10197.1.401.2`，65536 次迭代，keylen 16）+ **SM4-CBC**
  （OID `1.2.156.10197.1.104.2`）；OpenSSL 的 PBKDF2 实现不支持 SM3 作 PRF。
  反过来，GmSSL 也读不了 OpenSSL 生成的 SM2 私钥 PEM（`private key decryption failure`）。
- **解决**：写 `scripts/gmssl_key_dump.py`——纯标准库（`hashlib.pbkdf2_hmac('sm3')`
  + `openssl enc -d -sm4-cbc`）把加密私钥解开，输出 `d`/`x`/`y`，
  再和本实现用同一个 `d` 算出的公钥对拍。
- **反思**：这是**工具链互操作性问题**，不是被测代码的问题。
  验证的正确姿势是「用同一个私钥在两边算，看结果是否一致」，
  而不是硬要把两边的密钥文件格式打通。

### ⑦ DER 的 INTEGER 长度声明与实际字节数不符

- **现象**：本实现签的名交给 GmSSL 验签，GmSSL 报
  `asn1_length_le: 33 <= 32 failed`，直接拒签。
- **原因**：我的 `der_write_integer()` 里，声明的长度与真正写出的字节数差 1。
  DER 的 INTEGER 还有两条规则容易踩：去掉前导 `0`；最高位为 1 时前面补**一个** `0x00`。
- **解决**：按 GmSSL `asn1_integer_to_der_ex` 的规则重写（`tools/sm2_der.c`），
  长度与写入字节数严格一致。
- **反思**：用 `openssl asn1parse` 把自己的 DER 打出来逐字节看，比读代码快得多。

### ⑧ 曲线参数 b 少抄了一个字节（最贵的一个坑）

- **现象**：SM2 签名互验**双向都失败**，但程序不报错、不崩溃；
  加密互验也失败。表现就是「怎么都对不上」，没有任何线索。
- **定位**：① 先确认两处头文件的曲线参数是否一致；
  ② 再用 **Python 按标准公式独立算一遍 ZA**，与程序输出对拍——
  一比就发现程序算出的 ZA 根本不是标准值。
  ③ 顺着 ZA 的输入串（`a`、`b`、`xG`、`yG`）逐个对，
  定位到 `b` 少了一个字节 `0x9D`：
  - 正确：`28E9FA9E 9D9F5E34 4D5A9E4B CF6509A7 F39789F5 15AB8F92 DDBCBD41 4D940E93`
  - 错误：`28E9FA9E 9F5E344D 5A9E4BCF 6509A7F3 9789F515 AB8F92DD BCBD414D 940E93`（整体错位一字节）
- **修正**：改回与 `SM2_sv.h` 逐字节一致的 32 字节数组后，
  两项签名互验立刻变 PASS。
- **反思**：**参数少一位不会报错，只会安静地产生错误结果。**
  验证密码实现时，「用另一套独立实现（甚至脚本）重算一遍中间量」比盯着代码看有效得多。

### ⑨ 把接收方公钥当成了 C1

- **现象**：加密互验失败，错误是 `sm2_do_decrypt(): decryption failure`
  （DER 已经能被 GmSSL 解析，所以问题出在内容而不是格式）。
- **原因**：驱动的 `x=`、`y=` 打印的是**接收方公钥**，
  而 DER 密文里要放的是 **C1 = [k]G 的坐标**。
  GmSSL 用错的 C1 去算 `[d]C1`，KDF 出来的密钥流全错，C3 校验必然失败。
- **解决**：驱动改为分别输出 `pubx/puby` 与 `c1x/c1y/c3/c2`，
  验证脚本改用 `c1x/c1y` 组装 DER。
- **反思**：同一个十六进制串在不同语境下含义不同（公钥 vs C1），
  输出格式设计上就要把语义写进**键名**里，而不是靠调用方记忆。

### ⑩ 验证脚本里的两个小坑

- `sm2_der` 的路径写错（`$BIN/sm2_der` 写成了 `bin/sm2_der`），找不到可执行文件；
- 十六进制大小写不一致导致明明相等却判 FAIL → 加 `up()` 统一大写再比。
- **反思**：交叉验证脚本本身也要被验证——所以脚本里有 `expected`/`actual` 双行输出，
  失败时能直接看出差在哪。

## 5.3 结论

1. **检测中心的 SM2/SM3/SM4 参考实现与国家标准一致**：
   曲线参数、ZA、签名、验签、加密、KDF、密文布局、SM3 填充与压缩、SM4 密钥扩展与轮函数，
   逐条对得上 GB/T 32918 / 32905 / 32907；
2. **与 GmSSL 3.2.0、OpenSSL 3.5.6 双向互验通过**，标准向量全部吻合，
   篡改类负例全部按预期失败；
3. **官方发布物与可编译源码同源**：镜像源码 95.3% 的代码行能在官方 PDF 中逐字找到；
4. **可复现**：一条 `build_guest.sh` + 一条 `verify_all.sh` 即可重跑全部 25 项验证；
5. **踩坑集中在三处**：外部库版本差异（MIRACL 8.x）、编码格式细节（DER/PEM/二进制向量）、
   参数抄写错误（少一个字节）。前两类靠读文档和工具对比解决，
   第三类**只能靠独立重算中间量来发现**。
