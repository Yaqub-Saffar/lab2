### 构建中踩到的两个坑

**坑 1：上游 `.c` 自带 `main()`，不能直接和我们的驱动链接。**
解决办法是用宏把上游的入口改名后重编：

```bash
gcc -O2 -Wall -I$SM/miracl/include -Dmain=scctc_unused_main -c -o build/SM3.o $SM/src/SM3.c
```

**坑 2：MIRACL Core 8.x 没有全局 `mip` 符号。**
按老写法 `extern miracl *mip;` 链接会报 `undefined reference to mip`；
即使绕过链接，用未初始化的 `mip` 也会让 `drv_sm2_sv` 直接段错误。
正确写法与上游一致——在函数内部建局部实例：

```c
miracl *mip = mirsys(10000, 16);
mip->IOBASE = 16;
```

（`mirsys` 是 MIRACL 8.x 的初始化入口，`IOBASE=16` 表示大端字节序。）

## 0.4 本实验驱动的构建

`scripts/build_guest.sh` 一次性完成两件事：重编上游源码（改名 main）、链接 5 个驱动。

```bash
bash ~/exp2/our/scripts/build_guest.sh
```

实测产物：

| 可执行文件 | 作用 |
| --- | --- |
| `bin/drv_sm3` | SM3 摘要（字符串 / 文件 / 标准输入） |
| `bin/drv_sm4` | SM4 单块加解密（16 字节） |
| `bin/drv_sm2_sv` | SM2 密钥生成、签名、验签（含自算 ZA） |
| `bin/drv_sm2_enc` | SM2 公钥加密、解密 |
| `bin/sm2_der` | SM2 签名 / 密文的 DER 编解码（用于与 GmSSL 交换） |
